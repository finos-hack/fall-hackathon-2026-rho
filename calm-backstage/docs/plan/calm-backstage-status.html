Deviations from the plan

  • D1The spec expected one implementation plan from writing-plans before building. Instead, each step gets its own technical plan in docs/superpowers/plans/ when it starts, so it can use the facts earlier steps found. A subagent implements each plan, one at a time. applied
  • D2The plan expected create-app to run on Node 26. Its prerequisite check refuses anything but 22.x or 24.x. The scaffold step ran once on the existing node@22; install, build and run all use Node 26, and engines.node was widened to "22 || 24 || 26". README records this. applied
  • D3The spec named isolated-vm as the Node 26 risk. Backstage 1.56 does not use it: yarn.lock has 0 matches, and templating is pure JS (nunjitsu). The native module that was proven instead is better-sqlite3, built and loaded on Node 26. documented
  • D4The spec said to copy the release schemas from @finos/calm-schema. That package (1.3.0) holds only release 1.3. @finos/calm-cli 1.71.0 ships dist/calm/release/1.0 to 1.3 in the exact layout the Hub's init expects, so step 2 copies from the CLI. applied
  • D5The plan expected the copied init-mongo.js to start cleanly. It crashes when /controls is missing (it reads .length of undefined). The upstream compose probably has the same bug (not checked). The script is unchanged; compose mounts an empty hub/mongo/controls and sets CALM_CONTROLS_BASE_PATH, as the script's own message says. Accepted by the lead. applied
  • D6The plan expected @finos/calm-cli 1.71.0 as a root dev dependency. .yarnrc.yml has npmMinimalAgeGate: 3d, and 1.71.0 was published today at 12:32Z, so it is quarantined. Nothing was changed to get round the gate. 1.69.0 (Nov 9) already clears it and gives the same generate output on our Hub pattern (tested in the scratchpad). Jim chose to add @finos/calm-cli to npmPreapprovedPackages and keep 1.71.0. applied
  • D8The spec put the Hub client in calm-backend. It lives in calm-common, so the catalog module and the backend share one client. The provider reads only the namespaces in config (calm.namespaces, default hackathon), because the Hub image also seeds upstream demo namespaces. Entity names are pattern-*, control-*, bundle-*-version. applied
  • D9The plan made anyOf choices require at least one item. The CLI requires an answer only for oneOf decisions, so anyOf is optional in the form. The options reader mirrors the CLI source at monorepo c7ce7fe1a (CLI 1.67.0). It has not been diffed against 1.71.0, but generate on 1.71.0 accepts the choices it builds. documented
  • D10The plan assumed the pattern URL would be in the Template's annotations; it is not. The URL is written straight into the calm:generate step. Choices are passed one expression per decision, and the CLI checks them, not our own code. The action uses its own spawn so a failure carries the CLI's stderr; executeShellCommand reports only the exit code. calm:generate supports dry runs. applied
  • D11The spec had no shared Node package. A new plugins/calm-node holds the CLI runner for both the scaffolder actions and calm-backend. Found: the form's required flag alone does not block Review, so the field checks its own values. Tasks sent through the API skip the field's check, so calm:fill must refuse open placeholders. In the seed pattern every placeholder sits on a fixed node, so the list does not change with the choices; only the node counts do. applied
  • D12The plan expected catalog:register to handle a local folder. It always adds a url location, and the catalog's real default allows only url locations (the extension point's doc says url and file). The CALM catalog module now allows file locations, and a new calm:register:local action adds the location and waits for the entity. applied
  • D13The plan did not account for the catalog living in memory: published services drop out of the catalog when the backend restarts, but their folders stay in output/. Step 7 adds a file glob location for output/*/catalog-info.yaml, and calm:register:local treats a match from that glob as already registered. Verified: after a backend restart the published services are back. applied
  • D7The plan did not say which Hub write API to use. The Hub has two. The seed uses the name-based /calm/namespaces/{ns}/... endpoints, because only those return a $id the CLI can fetch. Other findings: calm validate needs -c for localhost control URLs, and calm template -o treats a folder name containing a dot as a file. documented
